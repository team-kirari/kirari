# 갤러리와 타임라인

## 구현 상태

- 갤러리는 **전체보기 / 태그 / 앨범**으로 분류합니다. 태그·앨범 모드에서 항목을 선택하고 제목·태그·앨범·저작권자를 검색할 수 있습니다.
- 기존 고정 일러스트 6장을 갤러리에서 제외했습니다. 프로필과 홈 메인 일러스트는 유지합니다. 기존 원본이나 Git 이력은 삭제하지 않았습니다.
- 기록 메뉴의 표시 이름은 **타임라인**입니다. 기존 `#log` 주소를 유지합니다. 방명록과 이전 기록 화면의 장식 그림은 제거했습니다.
- 제공받은 이야기를 2049년 9월부터 2050년 12월까지 6개 사건으로 표시합니다. **가을비의 리프레인**은 `9–10월`의 한 사건이며, 내부에서 `9월`과 `10월` 부제로 나눕니다. 여러 달·해에 걸친 기간은 날짜 표시 문구에 쓰고 정렬 날짜는 시작일을 사용합니다. 본문에서 `## 부제`를 별도 줄에 쓰면 부제로 표시하며, HTML과 링크는 실행하지 않고 텍스트로 표시합니다.
- 초기 화면은 가로 중앙선 위아래에 사건 날짜·큰 제목·본문 3줄 미리보기를 번갈아 배치한 전체 타임라인입니다. 연도는 연도별 구간 상단에 한 번만 표시합니다. 작은 화면에서는 전체 타임라인을 좌우로 스크롤합니다.
- 타임라인의 `OUR CHRONICLE`, `우리의 시간`, 사건 선택 안내 문구를 제거했습니다. 사건을 누르면 누른 위치에서 확대되는 애니메이션으로 상세가 **타임라인 패널 안에서만** 열립니다. 블러와 클릭 차단은 패널 내부의 전체 타임라인에만 적용하며 페이지 전체 팝업을 사용하지 않습니다. 패널 안의 카드 바깥 빈 공간 클릭·Escape로 원래 타임라인에 돌아가고 해당 사건으로 포커스를 돌립니다. 모션 줄이기에서는 확대 애니메이션을 생략합니다.
- 상세는 바깥 패널 없이 카드와 양옆의 화살표만 표시합니다. 카드·화살표 전체 너비는 최대 780px, 높이는 최대 440px이며 패널 크기에 맞춰 줄어듭니다. 하단 점 탐색·안내·별도 닫기 버튼을 제거했습니다. 상세 화면은 고정 높이의 가로 슬라이드입니다. 휠·좌우 스와이프·좌우 방향키·카드 양옆의 이전/다음 화살표으로 이동하며 전체 타임라인으로 돌아올 수 있습니다. 긴 본문 위의 세로 휠은 먼저 본문을 스크롤하고, 끝에 도달한 뒤 사건을 넘깁니다. 방향키 이동은 슬라이드 영역에 포커스했을 때 동작합니다. 모션 줄이기에서는 즉시 이동하며 카드 확대·축소 효과를 끕니다.
- Firestore에 저장된 사건을 표시하며, 사건 통합이나 본문 기본값 보충을 클라이언트에서 자동 수행하지 않습니다.
- 관리자는 사건 추가·수정·삭제, 날짜·제목·본문 작성과 미리보기를 사용할 수 있습니다. 저장 전에 편집창에서 취소할 수 있습니다.

## 그림 등록과 저장 범위

브라우저 로컬 이미지 등록·조회·초기화 기능을 제거했습니다. 기존 IndexedDB 데이터는 자동 삭제하거나 서버로 이전하지 않으며 갤러리에서 사용하지 않습니다. 사진은 아래 private 저장소 업로드 경로로만 등록합니다. 갤러리는 이미지 원본 비율을 유지하는 메이슨리이며 넓은 화면 3열, 중간 화면 2열, 작은 화면 1열로 표시합니다.

**사진 업로드**는 관리자 로그인 인증 Worker → 비공개 원본 저장소 → 이미지 검증 → Pages 재배포 경로를 사용합니다. [업로드 서버 연결 안내](private-photos.md)의 미완료 설정이 필요합니다. 새로 배포된 갤러리의 SHA-256 이름 WebP를 표시하며, 확대창에서 관리자가 **그림 정보 편집**을 눌러 제목·태그·앨범·저작권자를 공용 저장할 수 있습니다. 업로드 접수만으로 공개 완료를 표시하지 않습니다. 공용 사진 숨김은 갤러리 목록과 홈 사진 위젯에서 제외하며, 기존 배포 파일·원본·Git 이력·다운로드 사본을 삭제하거나 접근 차단하지 않습니다.

## 공용 저장과 보안 규칙

앱에서 사용하는 Firebase 프로젝트와 운영 `firestore.rules`가 올바르게 연결되어 있어야 합니다. 타임라인의 최초 운영 등록 결과는 아래와 같습니다. 이번 기본값 제거 작업에서는 운영 데이터와 보안 규칙을 변경하지 않았습니다.

### Firestore 이전 완료

2026-11-18: 사용자 승인과 Firebase CLI 로그인 후 `kirari-fd643`의 `(default)` 데이터베이스에 기존 사건 6개를 하나의 트랜잭션으로 생성했고, 서버 재조회에서 6개 모두의 존재와 데이터 형식을 확인했습니다. 기존 문서는 덮어쓰지 않았습니다.

이후 앱의 기본 사건 본문과 기본값 병합 로직을 제거했습니다. 화면은 Firestore에서 받은 사건만 날짜순으로 표시하며 삭제 표시가 있는 사건은 제외합니다. 빈 저장소에는 빈 목록을, 최초 조회 중에는 로딩 안내를, 조회 실패·설정 누락 시에는 오류 안내를 표시합니다. 삭제되거나 누락된 사건을 코드로 복원하지 않습니다. 등록을 마친 임시 seed 스크립트는 제거했고, 테스트는 합성 데이터만 사용합니다. 이 코드 변경의 앱 배포와 실제 화면 확인은 아직 수행하지 않았습니다.

기본값 제거 후 린트·타입 검사 포함 빌드·전체 일반 테스트 100개가 통과했습니다. 빌드 JavaScript에 기존 기본 사건 본문이 없는 것을 확인했고, Firebase SDK의 비로그인 제한 목록 쿼리로 운영 사건 6개를 읽었습니다. Firestore 보안 규칙은 변경하지 않았으며 에뮬레이터 권한 검사는 이번에 재실행하지 않았습니다. 사용자 화면에서는 로딩 후 기존 6개 사건이 표시되는지 확인해야 합니다.

- `timeline/{eventId}`: 공개 사건의 날짜·제목·본문·revision·삭제 표시.
- `gallery/{imageSha256}`: 공개 그림의 제목·태그·앨범·저작권자·revision·숨김 표시. 이미지 URL이나 원본 파일을 Firestore에 저장하지 않습니다.
- 공개 읽기와 최대 200개 제한 쿼리를 허용합니다. Google 이메일 인증 및 `admins/{uid}.enabled`를 통과한 관리자만 쓸 수 있습니다. 모든 데이터는 공개용입니다.
- 트랜잭션과 revision으로 동시 수정 충돌을 감지합니다. 삭제 표시를 저장하고 화면에서 제외합니다.
- Firebase 미설정·규칙 거절·연결 실패 시 공용 저장 완료로 처리하지 않습니다. 타임라인을 읽지 못하면 기본 내용으로 대체하지 않고 연결 상태를 안내합니다.

## 검증과 사용자 확인

명령줄 검사는 `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`입니다. Firestore Emulator를 127.0.0.1:8088에 실행한 상태에서 `node --experimental-strip-types tests/archive.rules.emulator.mjs`로 게스트·멤버 A/B·관리자 A/B·미인증 관리자·다른 로그인 공급자의 권한, revision 충돌, 삭제 표시, 잘못된 날짜·태그·본문을 검증합니다. 실제 계정이나 사진을 테스트 데이터로 쓰지 않습니다.

이번 변경에서 타입 검사·린트·일반 테스트 96개·빌드를 통과했습니다. 새 archive 권한 검사와 기존 firestore·profiles·guestbook 권한 검사도 통과했습니다. Windows의 한국어 JVM에서 에뮬레이터 오류 메시지 리소스(`ko_KR`) 누락으로 기존 검사에 UNKNOWN·잠금 오류가 발생했고, 에뮬레이터를 `java -Duser.language=en -Duser.country=US -jar ...`로 재시작한 뒤 기존 검사를 다시 실행해 통과했습니다. 운영 Firebase에는 접근하거나 쓰지 않았습니다.

브라우저·화면 자동화는 실행하지 않았습니다. 사용자는 아래 항목을 확인해 주세요.

타임라인 통합·부제·가로 전체 보기·상세 슬라이드 변경 후에는 타입 검사, 린트, 일반 테스트 99개와 빌드를 통과했습니다. 이번 변경에서 Firestore 보안 규칙은 수정하지 않았으며 운영 연결·화면 조작은 확인하지 않았습니다. 읽기 오류는 권한 거절·연결 불가·잘못된 데이터로 구분하여 방문자에게 안내합니다.

1. 갤러리에 로컬 등록·초기화 버튼이 없어야 합니다. 배포된 가로·세로 이미지가 잘리지 않고 서로 다른 높이의 메이슨리로 표시되는지, 화면 너비에 따라 3/2/1열로 바뀌는지 확인합니다. 태그·앨범 선택 시 해당 그림만 보여야 합니다.
2. 초기 가로 타임라인에서 연도는 구간마다 한 번만, 사건은 날짜·큰 제목·본문 3줄로 보여야 합니다. 임의의 사건을 클릭·Enter로 열면 누른 위치에서 상세가 확대되고 배경이 흐려져야 합니다. 바깥 빈 공간·Escape로 닫고 해당 사건에 포커스가 돌아오는지 확인해 주세요. 가을비의 리프레인 내부에는 9월·10월 부제가 있어야 합니다. 휠·좌우 스와이프·화살표 버튼과 슬라이드 영역의 좌우 방향키로 앞뒤 사건을 이동해 보세요. 긴 본문은 먼저 끝까지 읽혀야 합니다. 모바일의 가로 넘김·본문 읽기·바깥 클릭과 모션 줄이기의 즉시 열기·이동을 확인해 주세요.
3. 규칙 적용 후 관리자로 사건을 추가·수정·삭제하고, 별도 방문자 브라우저에 반영되는지 확인합니다. 비관리자에게 작성 버튼이 없어야 합니다.
4. 공용 업로드 서버 연결 후 시험 사진 접수·이미지 검증·Pages 재배포·그림 정보 편집을 실제 환경에서 확인합니다. 배포 후 다른 브라우저에서도 같은 사진이 나타나야 합니다.

최근 카드 단순화·크기 조정 후 일반 테스트는 96개 통과, 3개 실패했습니다. 실패는 실행 환경의 루프백 연결 차단(`EACCES`, 2개)과 symlink 생성 권한 부족(`EPERM`, 1개)이며 타임라인 테스트는 모두 통과했습니다. 린트·타입 검사 포함 빌드는 통과했고 브라우저 화면 검증은 수행하지 않았습니다.

갤러리 로컬 저장 제거·메이슨리 변경 후 린트와 타입 검사 포함 빌드는 통과했습니다. 일반 테스트 98개 중 갤러리 검사를 포함한 95개가 통과했고, 로컬 서버 fetch 실패 2개와 symlink 생성 권한 오류(`EPERM`) 1개가 남았습니다. 운영 업로드·배포와 브라우저 화면 검증은 수행하지 않았습니다.

사진 업로드는 마스터키 대신 기존 관리자 로그인으로 요청하며, 저작권자 이름을 함께 저장합니다. 목록과 확대창의 표시는 `ⓒ 이름 님`입니다. 실제 Worker 배포·URL 연결은 완료했고 자동 검증·Pages 재배포의 남은 설정은 [사진 운영 안내](private-photos.md)를 따릅니다.

관리자 인증 업로드 연결 후 전체 일반 테스트 101개·이미지 파이프라인 테스트 4개·린트·타입 검사 포함 빌드가 통과했습니다. 로컬 서버·symlink 검사 3개는 샌드박스 제약을 벗어난 재실행에서 통과했습니다. 앱 소스 Pages 배포가 성공했고 운영 JavaScript의 사진 API 주소·저작권자 입력·마스터키 제거를 HTTP로 확인했습니다. 자동 공개 배포 범위는 사용자가 명시적으로 승인했으며 브라우저 조작·실계정 업로드는 아직 확인하지 않았습니다.

private 사진 파이프라인 수동 실행과 그 실행의 `photos-updated` 요청으로 자동 시작된 Pages 재배포가 모두 성공했습니다. 승인 당시 staging 사진은 0개였고 실제 사진 접수·화면 조작 검증은 수행하지 않았습니다.


사건 추가 옆 `순서변경`에서 모든 사건을 드래그하거나 위·아래 버튼으로 배치하고 `순서 저장`으로 일괄 저장합니다. 저장된 순서는 개요·상세·이전/다음 이동에 공통 적용합니다. 기존 데이터는 날짜순을 유지하고, 수동 순서 지정 후 새 사건은 끝에 추가됩니다. 사건의 날짜·표시 문구는 바꾸지 않습니다. 동시 수정·삭제는 revision 검사로 전체 저장을 중단하며, 취소 시 쓰기는 발생하지 않습니다.

`timeline/{eventId}`의 선택 필드 `order`는 0 이상 1,000,000,000 이하 정수입니다. 이 필드를 허용하는 `firestore.rules`를 운영 환경에 먼저 적용해야 순서를 저장할 수 있습니다. 이번 변경으로 실제 규칙·사이트 배포는 실행하지 않았습니다. 브라우저에서는 관리자 순서변경 → 드래그 → 저장 → 새로고침 후 개요·상세 순서 유지, 취소 시 미반영, 모바일 터치 및 긴 목록 스크롤을 확인해야 합니다.

순서변경 구현 후 일반 테스트 118개, 린트, 타입 검사 포함 빌드가 통과했습니다. Firestore 규칙 에뮬레이터용 순서 필드·쓰기 권한 테스트를 추가하고 구문 검사했으나 에뮬레이터 실행·운영 환경 저장·브라우저 조작은 확인하지 않았습니다.

드래그 개선: 움직이지 않는 패널에 포인터를 캡처하고, 드롭 전에는 원본 행을 재배치하지 않습니다. 포인터를 따라가는 카드·흐린 원래 자리·삽입 위치선과 가장자리 연속 자동 스크롤을 제공합니다. Escape 또는 포인터 취소는 해당 드래그만 취소합니다. 일반 테스트 119개, 린트, 타입 검사 포함 빌드가 통과했습니다. 실제 마우스·터치 조작과 시각적 효과는 사용자 확인이 남아 있습니다. 패널 안에서 행·버튼·빈 공간을 오가도 드래그가 유지되고, 가장자리에서 포인터를 멈춰도 스크롤되며, 놓은 위치에 사건이 들어가는지 확인합니다.

타임라인 개선: PC 전체 보기 안의 세로 휠을 가로 이동으로 처리하며, 끝에서는 페이지 스크롤을 허용합니다. 700px 이하에서는 전체 보기와 상세 사건 이동을 세로로 배치합니다. 각 사건의 월 앞에는 연도를 추가하지 않습니다. 편집창에서 `중요 사건 강조`와 최대 40자의 `짧은 부제목`을 설정할 수 있습니다. 강조 사건에는 점 테두리와 카드 배경을 적용하고, 부제목은 개요·상세·미리보기에 일반 텍스트로 표시합니다. 닫기 애니메이션의 마지막 축소·투명 상태를 패널 제거까지 유지하여 원래 크기로 복귀하는 프레임을 방지합니다.

선택 필드 `highlighted`(boolean), `subtitle`(최대 40자 문자열)을 클라이언트와 Firestore 규칙에서 검증하며 기존 문서도 계속 허용합니다. 운영 저장에는 갱신된 규칙 적용이 필요합니다. 이번 작업에서 운영 규칙·사이트 배포는 수행하지 않았습니다. 일반 테스트 120개, 린트, 타입 검사 포함 빌드와 archive Firestore 에뮬레이터 검사가 통과했습니다. 에뮬레이터에서는 게스트·멤버 A/B의 강조 수정 거절, 관리자 저장, 공개 읽기와 잘못된 필드 거절을 확인했습니다. 브라우저 검증은 수행하지 않았습니다. 사용자는 PC 휠 이동, 모바일 세로 스와이프·긴 본문 읽기, 강조·부제목 저장 후 재조회, 상세 닫기 시 깜빡임이 없는지 확인해야 합니다.
