# 공용 프로필과 Git 사진 등록

**2026-11-14 전환 상태:** 기존 사진 55장을 `kirari-private`으로 옮기고 앱 저장소에서는 제거했습니다. 마스터키 업로드·Actions 이미지 검증 코드를 추가했으며 Cloudflare Worker Secret과 저장소 간 토큰 연결은 아직 완료하지 않았습니다. [사진 등록·운영 연결 안내](private-photos.md)를 참고하세요. 사진은 계속 공개 Pages 파일이며 프로필 글 저장은 기존 Firebase를 사용합니다.

프로필 글은 기존 Firebase 프로젝트의 Firestore를 사용하며 Spark 무료 한도를 다른 기능과 함께 사용합니다. 사진은 GitHub Pages 정적 파일입니다. 새 업로드 API는 Cloudflare Workers Free를 사용하도록 구성하며 Firebase Storage·Functions·Blaze 결제 연결은 사용하지 않습니다.

## 사진 등록

| 캐릭터 | 구일러스트 | 신일러스트 |
| --- | --- | --- |
| 켄지 | `kirari-private/assets/profiles/kenji/old/` | `kirari-private/assets/profiles/kenji/new/` |
| 키요 | `kirari-private/assets/profiles/kiyo/old/` | `kirari-private/assets/profiles/kiyo/new/` |

1. 공개해도 되는 PNG/JPEG/WebP/GIF 파일을 해당 폴더에 추가합니다. 하위 폴더는 지원하지 않습니다.
2. EXIF 위치정보와 기타 민감 메타데이터를 확인합니다. 앱은 메타데이터를 제거하지 않습니다.
3. `npm run build`로 파일 형식·헤더 검사 (앱 자체 용량·픽셀 상한 없음)를 실행합니다. 전체 이미지 디코딩 검사는 아니므로 실제 표시도 확인해야 합니다.
4. 사진 변경은 비공개 `kirari-private` 저장소에 커밋·푸시합니다. 앱의 `src/assets/`에는 다시 넣지 않습니다. 자동 연결 완료 후 private workflow와 Pages 배포가 차례로 성공하면 반영됩니다.

GitHub 웹에서도 해당 폴더의 Add file → Upload files로 추가할 수 있습니다. 사진 수와 캐릭터별 합산 용량의 앱 제한은 없습니다. 서비스의 저장·배포 한도는 그대로 적용됩니다. 코드에서 사진 목록을 직접 편집할 필요는 없습니다. 개발 서버 실행 중 추가했다면 파일 감시로 반영되며, 누락될 때는 개발 서버를 재시작합니다.

일러스트 설명 문구 바로 위에는 현재 선택된 버전 이름 하나만 계속 표시합니다. 이름 옆 전환 표시를 누르면 다음 버전으로 순환하며, 이 스위치는 각 캐릭터의 등장 사진만 전환합니다. 외형 참고 사진은 갤러리 태그로 가져오므로 바뀌지 않습니다. 전환할 때마다 대상 버전에서 관리자가 체크해 공용 저장한 사진 중 하나를 새로 무작위 선택하고 디코딩이 끝난 뒤 사진 자체를 회전하지 않고 같은 타원 궤도의 앞·뒤에서 같은 방향으로 반 바퀴 이동하며 0.7초 동안 자리를 교체합니다. 가로 반경은 20%, 앞뒤 높이 차이는 10%이며 한 바퀴를 더 돌지 않습니다. 전체 이동에 cubic-bezier(.4, 0, .2, 1) easing을 적용하고, 크기는 원래 크기를 넘지 않으며 도착 위치에서 튕김 없이 멈춥니다. 다음 버전으로 바꿀 때도 같은 방향을 유지합니다. 전환 중에는 중복 클릭을 막고, 모션 줄이기 설정에서는 즉시 전환합니다. 일반 사진의 무작위 표시 안내는 화면에 출력하지 않습니다. 그림 파일은 object-fit: contain과 하단 정렬로 일러스트 영역의 밑변에 맞춥니다(파일 내부 투명 여백은 변경하지 않습니다). 선택한 버전에 체크된 사진이 없으면 구·신으로 분류하지 않은 기존 임시 기본 그림을 표시합니다. 다른 버전의 사진으로 대체하지 않습니다. 구·신 선택은 두 캐릭터가 공유합니다. 한쪽에서 구일러스트를 선택하면 다른 캐릭터로 전환해도 구일러스트부터 표시하며 신일러스트도 동일하게 연동됩니다. 현재 선택은 방문자가 보는 화면의 임시 상태이고 프로필 화면에 새로 진입하면 신일러스트로 시작합니다.

사진 삭제는 Git에서 파일을 제거하고 다시 배포하면 반영됩니다. 이전 Git 커밋·외부 캐시·이미 다운로드된 사본까지 삭제되는 것은 아닙니다. 기존 IndexedDB 사진은 자동으로 공개하거나 이전하지 않으며 이 코드에서는 읽지도 않습니다. 필요한 사진은 원본 파일을 위 폴더에 직접 등록하세요. 이전 브라우저 데이터 삭제가 필요하면 해당 사이트의 브라우저 저장 데이터를 지울 수 있습니다(다른 사이트 설정도 초기화될 수 있습니다).

프로필의 말풍선과 말투·호칭 편집 항목은 제거했습니다. 기존 말투·호칭 데이터는 저장 스키마 호환성을 위해 유지하며 화면에 표시하지 않습니다.

관리자 편집창에서 구·신 버전별 사진 체크박스로 등장 후보를 선택합니다. 전체 선택·선택 해제와 현재 선택 개수를 제공하며, 취소하면 변경을 버립니다. ‘공용으로 저장’은 글과 사진 선택을 같은 트랜잭션으로 저장합니다. 새로 Git에 추가한 사진도 관리자가 체크해 저장하기 전에는 등장 후보가 아닙니다. 미선택 사진도 공개 배포 파일이며, 체크 해제는 비공개 접근 통제가 아닙니다. 선택이 비어 있거나 파일이 배포에서 사라지면 임시 기본 그림으로 대체합니다.

## 공용 프로필 규칙 적용

문서는 `profiles/kenji`, `profiles/kiyo`이고 `{ profile: {모든 프로필 필드}, revision: 양의 정수, photoSelection: {old: {파일명: true}, new: {파일명: true}} }` 구조입니다. 공개 글만 저장합니다. 사진 Blob이나 URL은 Firestore에 저장하지 않고 선택한 파일명만 저장합니다. 이전 문서에 photoSelection이 없으면 빈 선택으로 읽습니다. 관리자가 저장할 때 새 필드를 추가합니다. 새 규칙에서 photoSelection을 허용하는 변경도 운영 규칙에 병합해야 합니다. 관리자가 ‘공용으로 저장’을 누를 때 트랜잭션으로 저장 버전을 확인하며, 충돌 시 편집창을 닫고 최신 글로 다시 편집해야 합니다. 취소는 공용 데이터를 바꾸지 않습니다.

`firestore.rules`는 사용자가 제공한 기존 운영 규칙에 프로필·사진 선택 규칙을 추가한 전체 파일입니다. 기존 관리자 조회·화면 설정·좋아요·메시지·방명록 규칙은 그대로 보존했습니다. `firebase.json`도 이 전체 파일을 참조합니다. `firestore.profiles.rules`는 프로필 부분만 있는 참고용 파일이므로 이것만 운영 규칙 전체로 교체하면 안 됩니다.

Firebase Console → Firestore Database → 규칙에서 현재 규칙을 백업한 뒤 `firestore.rules` 전체 내용으로 교체하고 게시합니다. 이 파일을 만든 이후 운영 규칙을 추가로 수정했다면 최신 규칙과 먼저 병합해야 합니다. 이 작업에서는 실제 Firebase 규칙·배포·실데이터를 변경하지 않았습니다.

프로필은 누구나 개별 조회할 수 있고, 이메일 인증된 Google 사용자 중 `admins/{uid}.enabled == true`인 관리자만 쓰도록 제한합니다. 지원하지 않는 캐릭터 문서·목록 조회·문서 삭제는 허용하지 않습니다. 초기화가 필요하면 필드를 편집해 저장합니다. 클라이언트·규칙에서 필드 타입·허용 키·길이·숫자 범위·대표색과 저장 버전을 검사합니다. 모든 문자열은 React 텍스트로 표시합니다.

## 검증

`npm run lint`, `npm run typecheck`, `npm test`, `npm run build`를 실행합니다. 프로필 전용 권한 검사는 포트 8089의 로컬 Firestore 에뮬레이터에서 `node --experimental-strip-types tests/profiles.rules.emulator.mjs`로 실행합니다. 게스트·멤버 A/B 쓰기 차단, 관리자 A/B 공용 저장, 방문자 실시간 반영, 잘못된 값·버전 충돌·관리자 해제를 검사합니다. 기존 전체 규칙 검사는 포트 8088에서 `tests/firestore.rules.emulator.mjs`, `tests/guestbook.rules.emulator.mjs`를 순서대로 실행합니다. 프로필 테스트도 `PROFILES_EMULATOR_PORT=8088` 환경변수를 지정하면 같은 에뮬레이터에서 전체 규칙을 검증할 수 있습니다.

사용자가 실제 화면에서 확인할 항목:

- 데스크톱·모바일에서 편집창이 중앙에 열리고 긴 내용을 내부 스크롤할 수 있는지
- 한쪽에서 구·신을 선택한 뒤 다른 캐릭터로 전환해도 같은 버전이 표시되고, 빈 버전은 임시 기본 그림 안내가 나오는지. 스위치가 설명 문구 바로 위에 있고, 양방향 궤도 전환·연속 클릭·모션 줄이기가 정상인지
- 외형 탭에 해당 캐릭터 태그가 있는 갤러리 그림만 표시되고 프로필용 그림은 제외되는지. 구·신 전환 후에도 외형 사진 선택이 유지되는지
- 편집창에서 일부 사진만 체크해 공용 저장한 후 체크된 사진만 무작위로 나오고, 취소·전체 해제·새 파일 추가·삭제된 파일 처리가 올바른지
- 운영 규칙 적용 후 관리자 저장이 새로고침·다른 브라우저에도 유지되고 일반 방문자는 수정할 수 없는지
- 편집 취소가 공용 글을 바꾸지 않고, 두 관리자의 동시 편집은 충돌로 안내되는지

로컬 에뮬레이터 검사는 실제 Firebase 권한·호스팅·브라우저 화면 확인을 대신하지 않습니다.

현재 통합 규칙의 로컬 검증 결과: 프로필·사진 선택 권한 테스트와 린트는 통과했습니다. 기존 전체 규칙 테스트는 응답 대기로 완료되지 않아 중단했고, 방명록 회귀 테스트는 posting 문서 삭제 차단 확인에서 예상한 PERMISSION_DENIED 대신 에뮬레이터 UNKNOWN 응답을 받아 실패했습니다. 따라서 기존 기능 전체의 회귀 검증 완료로 보고하지 않습니다. 사용자가 제공한 기존 규칙은 내용 변경 없이 보존했습니다.


프로필은 성(`surname`)과 이름(`name`)을 따로 편집하고 성·이름 순서로 표시합니다. 성은 비워 둘 수 있습니다. 켄지의 한글 이름 크기를 줄이고 한자 이름은 14px로 키웠습니다. 직업/소속 항목은 제거했습니다. 나이는 최대 80자의 자유 텍스트이며 표시할 때 뒤에 ‘세’를 붙입니다(이미 ‘세’로 끝나면 중복하지 않음). 빈 나이는 ‘—’로 표시합니다.

이전 단일 이름·직업 스키마는 읽을 때 성을 빈 값으로 추가하고 직업을 제외합니다. 기존 전체 이름은 임의로 분리하지 않으므로 편집창에서 성과 이름을 직접 나눠 주세요. 다음 저장부터 새 스키마를 사용하며, 저장하려면 변경한 `firestore.rules`를 운영 규칙에 먼저 반영해야 합니다. 이번 변경에서는 운영 규칙이나 실데이터를 수정하지 않았습니다.


성·이름 분리 변경 검증: 타입 검사, 린트, 51개 단위 테스트, 프로덕션 빌드와 로컬 Firestore 프로필 권한 테스트를 통과했습니다. 프로필 권한 테스트는 분리한 성·문자 나이 저장, 잘못된 타입·과도한 길이·직업 필드 거부, 기존 문서의 새 형식 저장을 포함합니다. 이번에는 기존 전체 규칙·방명록 테스트를 다시 실행하지 않았으며 앞선 회귀 검증 제한은 남아 있습니다. 브라우저는 열지 않았습니다. 화면에서는 성·이름 입력 분리, 켄지의 긴 성 줄바꿈과 글자 크기, 한자 이름 크기, 직업/소속 제거, 문자 나이 뒤 ‘세’ 표시를 데스크톱·모바일에서 확인해 주세요.


프로필 화면의 상단 기록 문구·하단 서명·공용 저장 안내를 제거하고 캐릭터 전환 버튼은 현재 보고 있는 캐릭터를 제외하고 상대의 성을 뺀 이름과 방향 화살표만 표시합니다. 외형 탭은 프로필 등장 사진 선택이나 구·신 버전과 독립적으로 `src/content.ts` 갤러리의 `tags`에서 ‘켄지’ 또는 ‘키요’를 찾아 표시합니다. 페어 그림에 양쪽 캐릭터 태그가 있으면 양쪽에 표시합니다. ‘프로필’ 태그가 있는 항목, 해당 캐릭터의 구·신 프로필 폴더 이미지, 임시 프로필 기본 그림은 제외합니다. 일치 항목이 없으면 빈 상태를 표시하며 프로필 사진으로 대체하지 않습니다. 갤러리 분류 필터와 검색도 이 태그를 사용합니다.


프로필 배경과 화면 장식은 대표 컬러와 분리한 캐릭터별 고정 기본색(켄지 `#8BA5CB`, 키요 `#D8A4B9`)을 사용합니다. 대표 컬러를 편집해도 배경은 바뀌지 않으며, 대표 컬러 항목의 색상칩과 HEX 값은 저장된 대표 컬러를 표시합니다. 흑백 테마의 화면 장식은 기존처럼 회색을 사용합니다. 화면 확인 시 대표 컬러 변경 후 배경 유지와 색상칩 일치를 확인해 주세요.
