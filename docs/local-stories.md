# 로컬 이야기 작성과 비공개 저장소

이 문서는 `VITE_STORY_API_URL`이 없는 개발 서버의 로컬 모드를 설명합니다. 배포 사이트에서 저장 버튼으로 GitHub에 반영하는 기능은 [원격 이야기 저장](remote-stories.md)을 참고하세요. 기존 로컬 개인 글을 자동 이전하지 않습니다.

## 현재 구현 범위

`npm run dev`에서 이야기 → 새 글 쓰기로 제목·작가명·본문·폰트를 작성하고, 미리보기 또는 함께 보기로 확인한 뒤 로컬에 저장할 수 있습니다. 폰트는 사이트 기본이 초기값이며 페이퍼로지·온글잎 콘콘체·리디바탕체·조선일보명조체·갈무리14를 선택할 수 있습니다. 선택한 웹 폰트만 요청하고 로딩 실패 시 사이트 기본 폰트와 안내를 표시합니다. KoPub은 제공하지 않습니다. [폰트 출처·배포 조건·파일 정보](story-fonts.md)를 참고하세요.

읽기 화면과 미리보기는 같은 컴포넌트를 사용합니다. 배경과 글자색은 사이트 테마를 따르며 종이 질감·페이지 넘김·본문 전용 스크롤은 없습니다. 한 줄에 `***`만 입력하거나 붙여넣으면 미리보기와 읽기 화면에서 장면 전환으로 표시합니다. 편집 원문에는 `***`가 남아 일반 텍스트처럼 실행 취소·재편집할 수 있습니다. HTML·링크·이미지는 실행하거나 원격으로 불러오지 않고 텍스트로 표시합니다.

작성한 글은 선택한 checkout의 `stories/<UUID>.json`에 저장합니다. 목록·재조회·수정과 수정 revision 충돌 감지를 제공합니다. 글이 없으면 ‘아직 아무것도 없어요’만 표시합니다. 예시 글은 생성하지 않습니다.

## 저장소 선택

1. 서버 전용 환경변수 `KIRARI_PRIVATE_REPO_DIR`가 있으면 해당 경로를 사용합니다.
2. 일반 로컬 실행에서는 프로젝트 옆 `../kirari-private` 폴더가 있으면 사용합니다. 현재 작업 폴더 기준 `D:\Develop\Git\kirari-private`입니다.
3. 없으면 기존 `.local/kirari-private`를 사용합니다. CI는 명시적 환경변수가 없으면 항상 `.local/kirari-private`를 사용합니다.

다른 경로를 지정할 때는 추적하지 않는 `.env.local`에 설정하고 개발 서버를 다시 시작합니다.

```dotenv
KIRARI_PRIVATE_REPO_DIR=D:/path/to/kirari-private
```

이 경로는 `VITE_*` 변수가 아니며 클라이언트에 설정값을 주입하지 않습니다. 사진도 같은 저장소의 기존 공개 승인된 `assets/`만 사용합니다. checkout 전체나 `stories/`, `staging/`, `.git`을 Vite의 정적 파일 경로로 제공하지 않습니다.

## 저장과 원격 반영의 구분

화면의 ‘로컬에 저장’은 해당 기기의 checkout에 파일을 씁니다. 자동 `git pull`, commit, push나 배포는 하지 않습니다. 원격에서 받은 글은 개발 서버 재시작 또는 이야기 목록 재조회 시 읽습니다. Git 갱신은 로컬 변경을 확인한 뒤 직접 수행합니다.

```powershell
git -C D:\Develop\Git\kirari-private status --short
# 검토 후 해당 저장소에서 commit·push 또는 pull --ff-only 수행
```

GitHub Pages에는 이야기 원문을 번들·정적 JSON으로 넣지 않습니다. 운영용 Worker를 연결하면 Pages에서도 원격 글 작성·열람을 제공하며 로컬 글과 별도 경로를 사용합니다. 로컬 서버는 운영 서버로 배포하거나 프록시로 공개하지 않습니다.

## 비밀번호와 로컬 작성자

열람 비밀번호는 한글을 포함해 글자 수 제한 없이 설정할 수 있으며, 설정·열람 입력란에 입력값을 그대로 보여 줍니다. 원문 비밀번호는 저장 파일·브라우저 영구 저장소에 기록하지 않고 서버에서 무작위 salt와 scrypt로 해시합니다. 해시는 API 응답에 포함하지 않습니다. 비밀번호가 있는 글은 목록에서 제목·작가명을 숨깁니다. 해제 결과는 현재 화면의 메모리에만 있고 다시 열면 비밀번호를 입력합니다. 변경 화면에서 빈 비밀번호는 기존 값을 유지하며, 비밀번호 설정을 끄면 해제합니다.

이 서버는 **같은 기기에서 실행하는 한 명의 로컬 작성자용**입니다. 루프백 연결·Host·Origin·같은 출처 전용 헤더를 검사하고 외부 CORS를 허용하지 않습니다. 작성자는 로컬 파일 접근 권한이 있으므로 별도 수정 메뉴에서 비밀번호 없이 글을 편집할 수 있습니다. 비밀번호는 로컬 작성자나 저장소 관리자에게 원문을 숨기는 암호화가 아닙니다. 공유 기기 사용자 분리·실서비스 로그인·작성자별 private 권한을 구현한 것으로 취급하지 않습니다.

수정 전 내용은 Git으로 commit해 둔 경우 Git 이력으로 관리할 수 있습니다. 자동 초안 저장·휴지통·삭제·복원·이미지 첨부는 아직 없습니다. 페이지 새로고침·닫기에는 미저장 경고가 있지만 사이트 내 메뉴 이동 전에는 저장해야 합니다.

## 확인 항목

명령줄 검사는 합성 글만 사용하며 실제 개인 글을 테스트 자료로 쓰지 않습니다. 브라우저 화면 검증은 사용자가 수행합니다.

- 새 글에 제목·본문을 입력하고 한 줄의 `***`를 입력하거나 여러 문단과 함께 붙여넣습니다. 미리보기에서 별 세 개와 여백이 보여야 합니다.
- 블루·핑크·흑백 테마를 바꿀 때 본문 배경·글자·장면 전환 색이 따라야 합니다.
- 기본 폰트와 명조·고딕을 선택하고 저장·재조회 후 유지되는지 확인합니다. 읽기 화면의 폰트 변경은 저장된 글의 설정을 바꾸지 않습니다.
- 한글 비밀번호로 저장한 뒤 목록에서 열 때 입력값이 보이고 올바른 값으로만 열리는지 확인합니다.
- 저장 후 private checkout의 `stories/`에 파일이 생기고, 서버 재시작 후에도 목록과 수정 내용이 유지되는지 확인합니다. 자동으로 GitHub에 반영되지는 않습니다.
- PC·모바일에서 본문이 가로로 넘치지 않고 화면 전체가 세로로 스크롤되는지 확인합니다.

구현 참고: [Vite 서버 파일 접근 제한](https://vite.dev/config/server-options#server-fs-allow), [Node.js scrypt](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback).

빈 비밀번호는 설정할 수 없으며, 요청 전체 용량 제한은 유지합니다.
