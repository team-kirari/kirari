# 로그

주사위 아이콘의 `로그` 메뉴(`#trpg`)를 제공합니다. AfterTheRoll의 시네마틱 내보내기 데이터 형식, 장면 이벤트 처리, 이미지 배치·카메라, BGM 재생 로직을 현재 사이트 스타일에 맞춰 적용했습니다. 실제 로그 자료는 복사하지 않았습니다.

## 등록과 열람

- 관리자는 **로그 등록**에서 제목, 시네마틱 HTML 파일, 열람 비밀번호를 입력합니다. `const B64 = '…';`에 `rollscene-studio-project-v1` JSON을 포함한 내보내기 파일만 지원합니다. CCA·Roll20·코코포리아 원본 HTML, 텍스트, 임의 HTML은 받지 않습니다.
- 파일 확장자·MIME·내부 형식을 검사합니다. 사용자 요청에 따라 앱의 파일 크기·요청 크기·저장 총량·로그 개수·대사 수·이벤트 수 제한을 제거했습니다. rich text 깊이와 화자·채널 등 필드의 형식 검증은 유지합니다. 브라우저·Worker 메모리 및 GitHub API 자체의 처리 한계까지 없어지는 것은 아닙니다.
- 파일을 선택하면 파일명을 유지하고 표시 가능한 첫 5개 대사를 미리 보여 줍니다. 등록·확인·열람 비밀번호 입력은 한글을 포함한 일반 텍스트로 표시하며 글자 수 제한을 두지 않습니다.
- 비밀번호는 필수입니다. 카테고리에 들어오면 비로그인 방문자에게도 등록된 로그의 제목 목록을 먼저 표시합니다. 목록에서 로그를 누르면 해당 제목의 비밀번호 입력 화면을 엽니다. 목록 API는 ID·제목·수정 가능 여부·날짜·시작 장면 미리보기만 반환하며 본문·화자·비밀번호·해시는 포함하지 않습니다. 수정 버튼은 작성자인 활성 관리자에게만 표시합니다. 이는 제목 목록과 시작 장면을 먼저 보여 달라는 사용자 지시에 따른 공개 범위입니다.
- 비로그인 방문자도 올바른 비밀번호를 입력하면 일반 로그와 시네마틱 보기를 이용합니다. 일반 로그는 같은 화자·같은 포트레이트·같은 채널의 연속 대사를 묶어 이름과 초상을 한 번만 표시하고, 묶음 80개씩 페이지를 나눕니다. 상단 시네마틱 보기 버튼은 현재 페이지의 첫 대사부터 시작하며, 닫으면 재생하던 대사의 페이지로 돌아갑니다. 개별 대사에는 재생 버튼을 표시하지 않습니다.
- 일반 로그에서 초상·본문 이미지, 강조·줄바꿈·목록·표·주사위 결과 서식을 표시하고 이야기 화면과 같은 글씨체 목록에서 선택합니다. 초상은 4rem 정사각형 크기를 유지하고 이미지 위쪽을 기준으로 1.3배 확대해 자릅니다. CSS transform 재확대 대신 실제 이미지 요소 크기를 130%로 지정하며, 시네마틱 초상의 drop-shadow 필터를 제거했습니다. 두 초상에 image-rendering smooth를 지정하고 미지원 브라우저는 auto를 사용합니다. 계단 현상 개선 여부는 실제 화면 확인이 필요합니다. 일반 로그 대사 묶음의 위아래 여백과 본문 단락 사이 여백을 줄였습니다. 나레이션은 이름과 색상 배경 없이 가운데 정렬합니다. 상단에는 BGM 1·BGM 2 조절과 시네마틱 보기 버튼을 표시합니다. BGM·페이지 번호 버튼·글꼴 선택·시네마틱 보기를 하나의 스티키 도구 영역에 모읍니다. 페이지 번호는 가운데 정렬하고 이전/다음 버튼은 표시하지 않습니다. 글꼴 드롭다운은 시네마틱 보기 바로 왼쪽에 둡니다. 페이지 번호가 많으면 현재 페이지 주변과 처음·마지막 번호만 표시합니다. 현재 페이지 첫 대사부터 시네마틱을 시작하며 닫으면 재생하던 원본 대사로 돌아옵니다.
- 시네마틱은 대사 타이핑·즉시 표시·구두점 지연·속도 선택·자동 재생·좌우 방향키·Space/Enter·Escape 닫기를 제공합니다. 오른쪽 위에 BGM 1·2, 자동 재생, 대사 속도를 모으고, 이전 버튼은 말풍선 오른쪽 위에 둡니다. 다음은 말풍선·장면 클릭이나 키보드로 진행하며 다음 버튼·대사 수·전체 화면 버튼·클릭 안내·세모 표시는 제공하지 않습니다. 포트레이트는 말풍선 위에 배치하며 데스크톱은 왼쪽 정렬·화면 높이 최대 60%, 모바일은 중앙 정렬·최대 60%로 표시합니다. 말풍선과 상단 조작부 공간을 확보하면서 남은 높이에 맞춰 이미지를 줄입니다. 말풍선은 이름과 대사 한 줄 정도의 최소 높이에서 내용에 따라 늘어나며, 데스크톱은 화면 높이 40%, 모바일은 45% 상한 이후 내부에서 스크롤합니다. 스크롤바는 시네마틱 색상에 맞춘 얇은 형태로 표시합니다. 일반 로그와 달리 시네마틱 나레이션에는 가운데 정렬을 강제하지 않습니다. 긴 대사는 타이핑에 따라 스크롤하고 주사위 표는 즉시 표시합니다. 모션 줄이기 설정에서는 대사를 즉시 표시합니다. 원본의 채널 표시 설정을 따르며 별도 채널 표시 옵션은 제공하지 않습니다.
- 이미지와 음악은 별도 옵션 없이 기본으로 불러옵니다. 일반 로그의 초상·본문 이미지와 시네마틱 배경·전경·필드 오브젝트·이미지 전용 장면을 표시합니다. 내장 PNG/JPEG/WebP/GIF data URL은 MIME·base64·파일 시그니처를 검사합니다. 디코딩 후 가로·세로 16,384px 및 4천만 픽셀 상한을 확인합니다. 손상·실패 이미지에는 안내를 표시합니다.
- 허용 외부 호스트는 `files.d20.io`, `assets.ccfolia.com`, `storage.ccfolia-cdn.net`, `images.unsplash.com`, Discord 이미지 CDN 두 곳과 Amazon S3입니다. 이미지는 Referrer를 보내지 않지만 제공처에 사용자의 네트워크 요청은 전달됩니다. BGM은 두 채널을 지원하며 허용 호스트의 오디오·내장 오디오 또는 YouTube 재생을 제공합니다. YouTube 음악이 있으면 공식 iframe API와 임베드에 요청합니다. 브라우저가 자동 재생을 막으면 재생 버튼으로 시작합니다. 채널별 볼륨 슬라이더·스피커 아이콘 버튼과 자동 재생이 막혔을 때의 재생 버튼을 제공하며, 스피커 버튼을 누르면 음소거 아이콘으로 전환합니다. 음소거·볼륨 글자 대신 아이콘과 슬라이더를 표시하며 원본의 중지·반복·볼륨 설정을 반영합니다. 같은 곡은 일반 로그와 시네마틱 전환 때 재생 인스턴스를 유지합니다.
- 배경·전경·필드·음악의 순서를 보존합니다. 같은 대사 위치에서 같은 레이어가 반복되면 별도 장면으로 재생하고 마지막 대사 이후 이벤트도 유지합니다. 필드 위치·크기·회전·겹침 순서·figure 비율을 반영하며 중간 이동 프레임은 첫/마지막 위치로 압축합니다. 드래그·핀치·휠 카메라를 제공하며 초기화 버튼은 표시하지 않습니다. 뒤로 이동하면 이전 장면과 음악 상태를 복원합니다.
- 업로드 HTML의 스크립트나 raw HTML은 실행하지 않습니다. rich text는 허용한 태그·스타일을 React 요소로 출력합니다. 로그 본문·비밀번호·재생 자료를 브라우저 영구 저장소에 추가하지 않습니다.

## 저장과 권한

기존 이야기 Worker에 `/logs` 경로를 추가했습니다. 공개 API 주소 `VITE_STORY_API_URL`의 `/stories`를 `/logs`로 바꿔 요청하며, 새 클라이언트 Secret이나 환경변수는 필요하지 않습니다. 수정한 코드에서는 기존 이야기 데이터와 분리하여 **`team-kirari/kirari-private`의 `web-trpg-logs/entries/{UUID}.json`·`index.json`**에 저장합니다. index도 private 저장소에만 존재합니다. 본문과 목록은 raw Contents API로 읽어 1MB 초과 파일도 처리합니다. 원본은 개별 Git blob으로 접수하고 원본 파일과 index를 같은 커밋으로 갱신합니다. 이야기 기능의 기존 저장 한도는 유지합니다.

기존 `archive.json`과 구형 index는 계속 읽습니다. 최신 목록 정보가 있는 기존 로그는 새 로그 등록 시 다시 읽거나 파싱하지 않습니다. 기존 로그를 수정하면 해당 로그만 개별 파일로 이전하고, 나머지 원본은 옮기지 않습니다. 삭제는 index에서 즉시 제외하며, 개별 파일이면 같은 커밋에서 현재 파일도 삭제합니다. 구형 archive에 남은 사본과 Git 이력은 이 작업으로 지워지지 않지만, index에서 빠진 ID를 archive에서 되살려 제공하지 않습니다. 일회성 index 재생성 스크립트도 현재 index를 기준으로 개별 파일과 구형 자료를 함께 읽어 삭제된 로그를 다시 추가하지 않습니다. 이전 Worker 코드로 되돌리면 이 index 규칙을 인식하지 못하므로 혼합 저장 이후에는 구형 Worker로 단순 롤백하지 않습니다.

등록 서버는 native Base64 디코더와 데이터 전용 검증을 사용합니다. 재생 장면·대사 묶음 생성은 열람하는 브라우저에서 수행하고, 날짜·썸네일은 새로 쓰는 로그에서 한 번 추출해 index에 반영합니다. 클라이언트가 보낸 제목·본문·비밀번호·revision·mutation, 서버의 작성자 권한과 데이터 형식 검증은 유지합니다.

원본 JSON은 [GitHub Git blob API](https://docs.github.com/en/rest/git/blobs)의 `utf-8` 인코딩으로 전달해 업로드 직전 Base64 재인코딩과 그에 따른 메모리 복사를 줄입니다.

비밀번호는 무작위 salt와 PBKDF2-SHA256 100,000회 해시로 보관합니다. 본문 읽기는 서버의 비밀번호 확인 후에만 허용하며 본문 직접 GET은 거부합니다. 등록·수정은 Firebase의 활성 Google 관리자 확인이 필요하고, 편집용 열람과 수정은 저장된 작성자 UID가 일치해야 합니다. 다른 관리자는 열람 비밀번호를 우회할 수 없습니다. 비밀번호 교체는 이후 열람 요청부터 반영되며 빈 비밀번호로 보호를 해제할 수 없습니다.

원본 HTML은 **실행하지 않습니다**. base64 내부 JSON에서 허용된 데이터만 읽고, 대사·제목은 React 텍스트로 표시합니다. 링크·스크립트·업로드된 HTML 문서 자체를 열지 않습니다. 원본·비밀번호·인증 토큰은 localStorage·IndexedDB에 저장하지 않습니다. API 응답에는 `private, no-store`를 적용하고 원본과 해시는 공개 빌드에 포함하지 않습니다.

원본은 private 저장소에 평문으로 보관되므로 저장소 관리자는 접근할 수 있습니다. 종단 간 암호화가 아닙니다. Git 이력과 열람자가 이미 받은 사본은 비밀번호 교체로 회수할 수 없습니다. 기존 이야기와 같은 Origin 검사·IP별 요청 제한·revision 충돌 검사·mutation 재시도·강제 갱신 없는 Git 커밋을 사용합니다. 원본과 index는 같은 커밋에서 갱신합니다.

`VITE_STORY_API_URL`이 없으면 개발 서버에서만 private checkout의 `trpg-logs/{UUID}.json`에 저장하는 로컬 모드를 사용합니다. 같은 기기의 개발용 기능이며 로컬 작성자 열람은 사용자 계정 인증을 대신하지 않습니다. Vite의 private 경로 차단 및 파일 제공 금지 규칙을 적용합니다. Pages에는 로컬 API가 없으며 서버 연결 안내를 표시합니다.

## 현재 제한과 남은 확인
