# 키라리 · Kirari · きらり

두 사람의 소개, 그림, 이야기와 작은 기록을 모으는 페어 홈페이지입니다.
캐릭터 일러스트 주위로 다양한 위젯이 겹쳐 떠 있는 화면을 중심으로 정적 아카이브를 만듭니다.

## 현재 상태

현재는 외관 미리보기 앱을 구현한 단계입니다. `npm ci` 후 `npm run dev`로 실행할 수 있습니다.
홈 위젯, 프로필, 갤러리와 이미지 확대, 이야기·기록의 준비 화면, 로컬 방명록 시연을 제공합니다.
Discord·서버 저장은 아직 구현하지 않았습니다. GitHub Pages 배포 워크플로는 `.github/workflows/pages.yml`에 구성되어 있습니다.
관리자 로그인은 Firebase Authentication의 Google 팝업 로그인을 사용합니다. 지정 이메일·이메일 인증·Google 로그인 공급자를 확인해 관리자 상태를 표시합니다.
실제 사용에는 Firebase 웹 앱 설정이 필요합니다. [관리자 로그인 설정 안내](docs/admin-login.md)를 따르세요.
GitHub Pages 정적 호스팅을 유지하며 Cloudflare Access·Worker는 필요하지 않습니다. 로그인 토큰은 메모리에만 보관해 새로고침하면 로그인이 해제됩니다.
현재 관리자 상태 표시는 UI 용도이며, 데이터 저장·수정 API와 서버 인가는 아직 구현하지 않았습니다.
컬러·메인 일러스트·경계 페더는 화면 설정에서만 조절하며, 새로고침하면 초기화됩니다.
좋아요는 현재 브라우저의 localStorage에 누적 횟수와 오늘 사용 횟수를 저장하고 한국 시간 자정마다 하루 5회 제한을 초기화합니다. 화면에는 누적 횟수만 표시하며 남은 횟수 안내는 표시하지 않습니다. 저장에 성공해 횟수가 증가할 때마다 작은 하트 세 개가 매번 무작위 방향·높이·크기·속도로 위로 튀어 올라 사라집니다. 모션 줄이기 설정에서는 이 효과를 생략합니다. 개발 모드(`npm run dev`)에서만 누적·오늘 사용 횟수를 지우는 초기화 버튼을 표시하며 프로덕션 빌드에는 표시하지 않습니다. 새로고침 후에도 유지되며 다른 방문자와 합산하지 않습니다. 저장소 삭제·변조나 다른 브라우저 사용을 막는 서버 제한은 아니며, 저장 실패와 손상 데이터는 안내 후 안전하게 처리합니다. Web Locks 지원 환경에서는 여러 탭의 동시 쓰기를 순서대로 처리합니다.
D-day는 하나의 위젯 안에 항목이 아래로 쌓입니다. 화면 설정에서 이름·기준일을 정하고 항목을 추가·삭제합니다. 새로고침하면 초기화됩니다.
홈의 이야기 위젯은 책갈피를 끼운 작은 책으로, 방명록은 포스트잇 두 장이 겹친 모양으로 표시합니다. 마우스를 올리거나 키보드 포커스를 두면 책 표지가 부드럽게 열리고 책갈피가 올라옵니다. 모션 줄이기 설정에서는 전환 애니메이션을 생략합니다. 두 위젯은 각각 이동할 수 있으며 최근 기록 위젯은 표시하지 않습니다.
모바일에서는 날짜와 D-day를 각각 왼쪽과 오른쪽에 나란히 배치합니다. 이야기와 방명록도 한 줄의 왼쪽과 오른쪽에 배치합니다.
방명록은 최근 1개를 홈에 표시하며 별도 방명록 화면과 현재 탭의 메모리에서 최대 20개를 공유합니다. 새로고침하면 사라지며 서버에 저장하지 않습니다.
프로필·갤러리는 기존 상단 메뉴와 사이드 메뉴에서 엽니다.
사진 위젯은 새로고침할 때만 랜덤으로 그림을 선택합니다. 시간이 지나거나 다른 페이지를 다녀와도 같은 사진을 유지합니다.
별도 문구 없이 원본 전체가 보이는 비율로 프레임이 맞춰집니다.
D-day는 한국 날짜를 기준으로 미래는 `D−N`, 과거는 `D+N`, 당일은 `D-DAY`로 표시합니다.

| 파일 | 역할 |
| --- | --- |
| `example.html` | 레이아웃, 색상, 상호작용의 디자인 참고 예제 |
| [docs/archive-requirements.md](docs/archive-requirements.md) | Discord 공동 아카이브의 장기 요구사항 |
| `README.md` | 사이트 기획, 디자인 방향, 개발 및 배포 안내 |
| `AGENTS.md` | 코드 작업 시 지켜야 할 보안 규칙 |

## 프로젝트 방향

### 먼저 만들 사이트

- React와 TypeScript로 구현하는 한국어 중심의 정적 사이트.
- Vite 개발 서버를 `npm run dev`로 실행.
- 빌드 결과인 `dist/`를 GitHub Pages에 배포.
- 공개해도 되는 프로필, 일러스트, 이야기, 로그를 저장소에서 관리.
- 검색과 필터는 공개 콘텐츠를 대상으로 브라우저에서 처리.
- 서버나 외부 계정의 Secret 없이 기본 화면을 개발하고 실행.

### 원본 프롬프트와의 관계

원본 프롬프트는 Cloudflare Pages/Functions, D1, R2, Discord OAuth2와
GitHub Private Repository를 사용하는 서버 기반 공동 아카이브를 제안합니다.
이번 단계에서는 사용자가 지정한 **GitHub Pages 정적 호스팅**을 우선합니다.
원본의 읽기 편한 아카이브, 한국어 UI, 모바일 대응, 안전한 콘텐츠 처리 원칙을 적용합니다.

GitHub Pages는 HTML, CSS, JavaScript를 제공하는 정적 호스팅입니다.
서버 API나 비밀키를 사용하는 작업은 별도 서버가 필요합니다.
관련 호스팅 특성은 [GitHub Pages 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)를 기준으로 합니다.

| 항목 | 초기 정적 사이트 | 서버 도입 이후 |
| --- | --- | --- |
| 소개·갤러리·이야기·로그 | 공개 콘텐츠로 제공 | 기존 화면 유지 및 확장 |
| 검색·태그·카테고리 | 공개 데이터 안에서 검색 | 권한에 맞는 서버 검색 |
| 글 작성·수정 | 저장소 파일 수정 후 재빌드 | 인증된 웹 에디터 |
| 이미지 설정 | 방문자 브라우저 안의 개인 설정 | 인증된 업로드 및 공용 설정 |
| 방명록·메시지 | 제공한다면 로컬 시연임을 명시 | 서버 저장과 운영 정책 필요 |
| Discord 로그인·명령어·알림 | 초기 범위에 포함하지 않음 | 인증 및 서명 검증 API 필요 |
| 공동·개인 자료 | 배포 데이터에 포함하지 않음 | 서버에서 매 요청 접근 권한 확인 |
| Private Repo 원본 저장 | 초기 범위에 포함하지 않음 | 서버와 Actions 저장 파이프라인 |

현재 로그인은 인증 상태 확인 용도입니다. 로그인 버튼이나 CSS로 글을 숨겨 비공개 자료의 접근 통제처럼 제공하지 않습니다.
서버 단계에서는 원본 프롬프트의 같은 오리진 API 요구도 다시 설계해야 합니다.
GitHub Pages를 유지하면서 외부 API를 연결한다면 쿠키, CORS, CSRF 정책을 별도로 검증합니다.

## 만들고 싶은 분위기

### 콘셉트: 캐릭터와 겹쳐 떠 있는 여러 위젯

큰 캐릭터 일러스트의 앞뒤로 프로필, 검색창, 플레이어, 메시지, 사진과 아이콘 패널이
여러 겹으로 떠 있는 구성을 지향합니다. 화면 전체가 하나의 커스텀 UI처럼 보이게 만듭니다.
크기와 위치가 다른 위젯을 풍성하게 배치하고, 반투명 표면과 테두리로 레이어의 깊이를 표현합니다.
홈은 시각적으로 밀도 있게 구성하고, 긴 글과 자료를 읽는 상세 화면은 읽기 편하게 정리합니다.

디자인 방향은 사용자가 제공한 네 장의 레퍼런스를 기준으로 합니다.
`example.html`은 구현 참고 자료이며, 레퍼런스와 충돌하는 문구나 배치를 그대로 따르지 않습니다.

| 레퍼런스 | 참고할 특징 |
| --- | --- |
| 이미지 1 · 블루 | 큰 캐릭터, 작은 검색창과 아이콘 버튼, 둥근 패널, 흰 테두리와 이미지 크롭 |
| 이미지 2 · 민트 | 캐릭터 앞뒤로 겹친 프로필·소개·사진 위젯, 반투명 표면과 부드러운 깊이감 |
| 이미지 3 · 화이트 | 비대칭 패널 구성, 사이드 메뉴, 다양한 크기의 기능 위젯과 넓게 걸친 캐릭터 |
| 이미지 4 · 스카이블루 | 화면 가장자리의 도구 아이콘, 말풍선, 얇은 프레임과 조밀한 UI 배치 |

레퍼런스에서는 위젯의 배치와 레이어 표현을 참고합니다.
이미지 속 캐릭터, 로고, 작가 표기와 문장은 사이트 콘텐츠로 가져오지 않습니다.
감성적인 영문 슬로건은 넣지 않으며, 예제에 있는 장식용 영어 문구도 실제 사이트에 옮기지 않습니다.
텍스트는 사이트 이름, 캐릭터 이름, 메뉴와 위젯의 기능·내용을 전달하는 데 사용합니다.

### 색상과 표면

예제 CSS의 주요 색을 초기 디자인 토큰으로 사용하되, 레퍼런스의 화이트·블루·민트 계열도 고려합니다.
메인 일러스트와 어울리는 주조색을 정하고 위젯마다 같은 색 체계를 공유합니다.

| 용도 | 색상 | 표현 |
| --- | --- | --- |
| 밀크 배경 | `#f8fafd` | 차갑지 않은 밝은 바탕 |
| 위젯 표면 | `#ffffff` | 불투명·반투명 패널의 기본색 |
| 아이스 보조 배경 | `#eff3fa` | 입력 영역과 작은 구획 |
| 기본 블루 | `#8398bd` | 브랜드와 주요 포인트 |
| 진한 블루 | `#5e759c` | 제목과 주요 조작 |
| 연한 블루 | `#dce6f4` | 선택 상태와 장식 |
| 기본 핑크 | `#efc6d7` | 두 번째 인물과 보조 포인트 |
| 진한 핑크 | `#b7819b` | 핑크 계열 강조 |
| 연한 핑크 | `#fae6ee` | 보조 카드와 배지 |
| 기본 글자 | `#526685` | 본문과 설명 |
| 테두리 | `#dfe7f1` | 카드와 영역 구분 |

파스텔 색은 넓은 배경과 장식에 사용하고, 작은 글자와 버튼은 충분한 대비를 확보합니다.
예제의 옅은 보조 글자를 그대로 답습하지 않고 실제 크기에서 읽기 쉬운지 확인합니다.
카드는 약 20~24px의 둥근 모서리, 흰색 또는 옅은 색 테두리와 은은한 그림자를 기본으로 합니다.
작은 도구 버튼과 입력창은 크기에 맞게 곡률을 줄이고, 반투명 패널은 겹침을 드러내는 데 사용합니다.
캐릭터 뒤의 패널, 캐릭터, 앞쪽 조작 위젯이 구분되도록 명도와 투명도를 조절합니다.

### 레이아웃과 이미지

- 큰 페어 일러스트가 여러 패널의 경계를 가로지르도록 배치하고, 위젯 일부는 그 앞에 겹칩니다.
- 뒤쪽 큰 패널 → 캐릭터 → 앞쪽 작은 위젯 → 도구 아이콘 순으로 레이어를 구성합니다.
- 프로필, 검색, 날짜, 플레이어, 이야기·방명록과 이미지 미리보기를 서로 다른 크기의 독립 위젯으로 배치합니다.
- 큰 사각 패널만 반복하지 않고 가로로 긴 입력창, 작은 정사각 버튼, 세로 도구 모음과 말풍선을 섞습니다.
- 상단 메뉴, 측면 아이콘과 위젯 제목으로 소개·갤러리·이야기·로그에 접근할 수 있게 합니다.
- 화면 가장자리와 일러스트 주변에도 작은 위젯을 두어 한 화면에 풍성한 구성을 만듭니다.
- 얇은 프레임, 구분선, 작은 기호와 이미지 크롭으로 UI 특유의 디테일을 더합니다.
- 글 상세와 목록은 장식보다 본문 너비, 행간, 정렬과 탐색 편의성을 우선합니다.
- 모바일은 일러스트 아래에 프로필 → 날짜·D-day·좋아요 → 메시지 → 갤러리 → 플레이리스트 → 이야기·방명록 순서로 위젯을 세로 배치합니다.
- 이미지의 비율과 주요 인물이 잘리지 않도록 하고, 장식이 버튼이나 글을 가리지 않게 합니다.

예제의 Kenji와 Kiyo 표기는 참고 콘텐츠입니다. 실제 표시 이름, 소개와 이미지는 교체하기 쉽게 분리합니다.
게시할 이미지와 글은 공개 권한을 확인한 자료만 사용합니다.

### 글꼴과 문장

한국어 본문은 Pretendard, SUIT, Noto Sans KR 계열과 시스템 글꼴을 고려합니다.
외부 폰트 없이도 레이아웃이 자연스럽게 보이는 대체 글꼴을 둡니다.
위젯 제목은 짧고 명확하게 쓰고, 크기와 굵기의 차이로 정보의 위계를 표현합니다.
큰 영문 감성 문구나 이탤릭 캡션을 메인 화면의 중심 요소로 사용하지 않습니다.
실제 안내와 오류는 짧고 이해하기 쉬운 한국어로 작성합니다.

### 움직임과 조작

위젯이 떠 있는 인상은 겹침, 위치, 그림자와 투명도로 먼저 만듭니다.
모든 위젯과 사진 패널은 기울기 없이 수평으로 배치합니다.
데스크톱에서는 홈 위젯 본문이나 사진을 잡아 마우스나 터치로 이동할 수 있습니다. 메뉴 모음은 한 덩어리로 이동합니다. 입력 필드와 슬라이더는 원래 조작을 유지하고, 버튼은 클릭과 드래그를 구분합니다.
위젯을 이동하면 즉시 가장 위에 표시되고, 놓은 뒤에도 유지됩니다. 다른 위젯을 이동하면 해당 위젯이 가장 위로 올라옵니다. 위젯 위치 초기화 시 겹침 순서도 초기화됩니다.
위젯에 포커스를 두고 방향키로 10px, Shift+방향키로 30px씩 조절할 수 있으며 드래그 중 Esc로 취소합니다. 700px 이하 모바일 화면에서는 이동을 끄고 세로 스크롤로 이용합니다. 데스크톱에서 이동한 위치는 모바일 배치에 영향을 주지 않습니다.
이동은 홈 영역 안으로 제한하고, 화면 크기가 달라지면 위치를 보정합니다.
배치는 페이지 이동 중 유지되며 새로고침하면 초기화됩니다. 화면 설정의 ‘위젯 위치 초기화’로 기본 배치로 돌아갑니다.
계속 움직이는 애니메이션은 필수 조건이 아니며, 적용할 경우 작은 범위에서 조작과 읽기를 방해하지 않게 합니다.
호버와 포커스에는 테두리·그림자·작은 위치 변화 등 일관된 피드백을 제공합니다.
홈에서 다른 화면으로 이동하거나 홈으로 돌아올 때만 **누른 지점에서 플랫한 리퀴드 색 면이 꾸물꾸물 번지는 효과**를 적용합니다.
홈 이외의 화면 사이에서는 전환 애니메이션 없이 바로 이동합니다.
처음에는 작은 색 덩어리가 생기고, 가장자리가 불규칙하게 출렁이며 사방으로 퍼져 화면을 덮습니다.
단순한 원형 확대나 물결 테두리 대신, 액체 외곽이 늘어나고 오므라들면서 유기적으로 변형되는 움직임을 만듭니다.
색 면은 입체적인 광택·굴절·그라데이션 없이 단색으로 표현하고, 누른 위젯에 어울리는 파스텔 색을 사용합니다.
화면이 색 면으로 덮이는 순간 다음 화면으로 바꾼 뒤 색 면을 걷어내거나 페이드해 내용을 드러냅니다.
`example.html`의 클릭 위치 기반 SVG 경로 확장과 외곽 변형을 구현 참고로 삼습니다.
위젯 내부의 좋아요·재생·입력 조작에는 전체 화면 전환을 발생시키지 않으며, 전환 중 중복 입력도 처리합니다.
`prefers-reduced-motion` 설정에서는 전환과 장식 애니메이션을 줄이거나 생략합니다.
카드 전체의 이동 동작과 내부의 좋아요·재생·입력 버튼은 각각 독립적으로 작동해야 합니다.
키보드 탐색, 포커스 표시, 이미지 대체 텍스트와 의미 있는 버튼 이름을 제공합니다.
음악을 연결하더라도 자동 재생하지 않으며, 시연 플레이어는 실제 음원이 없다는 사실을 표시합니다.

## 개발 구성 계획

| 항목 | 계획 |
| --- | --- |
| UI | React + TypeScript |
| 개발·빌드 | Vite |
| 스타일 | Tailwind CSS와 공통 디자인 토큰 |
| 패키지 관리 | npm, `package-lock.json` 커밋 |
| 라우팅 | GitHub Pages 새로고침에 대응하는 해시 기반 라우팅 |
| 콘텐츠 | 저장소 안의 공개용 TypeScript/JSON, 필요 시 Markdown |
| 검증 | 타입 검사, 린트, 핵심 동작에 필요한 테스트, 빌드 확인 |
| 호스팅 | GitHub Pages + GitHub Actions |

버전은 프로젝트 초기화 때 공식 문서와 호환성을 확인하여 고정하고,
사용하는 Node.js 버전을 저장소와 CI에 동일하게 기록합니다.

아래는 확장 목표를 포함한 구조입니다. 현재 UI는 `src/App.tsx`, 콘텐츠는 `src/content.ts`, 스타일은 `src/styles.css`에 구현되어 있습니다.

```text
kirari/
├── example.html                 # 원본 디자인 참고
├── docs/
│   └── archive-requirements.md   # Discord 공동 아카이브의 장기 요구사항
├── README.md
├── AGENTS.md
├── index.html                   # 앱 진입점
├── package.json
├── package-lock.json
├── vite.config.ts
├── src/
│   ├── components/              # 카드, 탐색, 공통 상태
│   ├── pages/                   # 홈, 소개, 갤러리, 이야기, 로그
│   ├── content/                 # 공개할 콘텐츠만 보관
│   ├── assets/                  # 빌드에서 처리하는 이미지
│   └── styles/                  # 토큰과 공통 스타일
├── public/                      # 그대로 공개되는 정적 파일
└── .github/workflows/           # 검사 및 Pages 배포
```

`example.html`은 참고 파일로 보존하고, 실제 앱은 컴포넌트와 콘텐츠로 나누어 구현합니다.
예제에 포함된 대형 인라인 이미지는 앱에서 별도 에셋으로 분리하고 최적화합니다.

## 로컬 실행과 검증 목표

Node.js 22.22.0 기준으로 다음 명령을 실행합니다.

```powershell
# 최초 설치
npm ci

# 로컬 개발
npm run dev

# 정적 검사와 테스트
npm run lint
npm run typecheck
npm test

# 배포용 파일 생성과 미리보기
npm run build
npm run preview
```

`dev`는 Vite 개발 서버, `build`는 타입 검사와 배포 파일 생성, `preview`는 빌드 결과 확인을 담당합니다.
기본 접속 경로는 `http://127.0.0.1:5173/kirari/`입니다.
화면 설정에서 페더를 0~40px 범위로 슬라이더 또는 숫자로 입력할 수 있습니다.
페더는 일러스트의 투명 경계에만 적용하고 내부 그림의 선명도는 유지합니다.
접속 주소는 명령 실행 후 터미널에 표시된 값을 사용합니다.
비밀키나 Discord 연결 없이도 기본 UI와 공개 콘텐츠를 확인할 수 있어야 합니다.

## GitHub Pages 배포

사이트 주소는 **https://team-kirari.github.io/kirari/** 입니다. Vite `base`는 `/kirari/`이며 메뉴는 해시 주소를 사용합니다. 예를 들어 `/kirari/#gallery`로 직접 들어가거나 새로고침해도 같은 정적 진입점을 사용합니다.

`.github/workflows/pages.yml`은 `main`에 push하면 검사와 빌드 후 `dist/`만 GitHub Pages에 배포합니다. Actions 탭에서 수동 실행할 수도 있습니다. `main` 대상 PR에서는 검사와 빌드만 실행합니다. Node.js 버전은 `.node-version`으로 고정하고 공식 액션은 전체 커밋 SHA로 고정합니다. Pages 쓰기 권한은 배포 작업에만 부여합니다.

저장소 Settings → Pages의 Source는 **GitHub Actions**를 사용합니다. Firebase 관리자 로그인을 사용하려면 Settings → Secrets and variables → Actions → Variables에 아래 공개 웹 앱 설정을 등록합니다. 이 값은 빌드에 포함되어 방문자에게 공개됩니다. OAuth Secret이나 서비스 계정 키는 등록하지 않습니다.

- `VITE_FIREBASE_API_KEY`
- `VITE_FIREBASE_AUTH_DOMAIN`
- `VITE_FIREBASE_PROJECT_ID`
- `VITE_FIREBASE_APP_ID`

설정이 없으면 공개 화면은 제공하고 로그인은 비활성화합니다. Firebase Authentication의 승인된 도메인에는 `team-kirari.github.io`를 추가해야 합니다. 로컬 `.env.local`은 커밋하거나 배포 아티팩트에 복사하지 않습니다.

배포 후 사용자가 이미지, 메뉴, `/kirari/#gallery` 직접 진입과 새로고침, 모바일 화면, 실제 Google 로그인을 확인해야 합니다. 명령줄 검사와 Actions 성공만으로 화면·실계정 검증을 완료했다고 간주하지 않습니다.

배포 방법과 기본 경로는 [Vite 공식 정적 배포 안내](https://vite.dev/guide/static-deploy.html#github-pages)를 참고합니다.
공식 문서 확인일은 **2026-11-04**이며, 실제 구성 시 Actions 버전과 호스팅 정책을 다시 확인합니다.
요금이나 무료 한도를 영구 보장하지 않으며, 사용량이 커지면 공식 제한을 확인합니다.

## 콘텐츠 관리와 저장 범위

초기 공용 콘텐츠는 저장소에서 수정하고 빌드·배포를 거쳐 반영합니다.
방문자가 브라우저에서 바꾼 메인 이미지는 공용 원본이나 다른 사람의 화면을 변경하지 않습니다.
이 기능을 구현한다면 이미지 Blob은 IndexedDB, 작은 화면 설정은 localStorage에 보관할 수 있습니다.
브라우저 데이터 삭제나 기기 변경 시 설정이 사라질 수 있음을 안내하고 초기화 기능을 제공합니다.
인증 토큰, 개인 아카이브와 비공개 대화는 이 저장 방식에 넣지 않습니다.

공개 빌드에 포함된 파일은 주소를 알거나 코드를 분석하면 누구나 읽을 수 있습니다.
화면의 숨김 처리, 비밀번호 입력 UI, 추측하기 어려운 파일명은 접근 통제가 아닙니다.
공개를 철회해도 이미 다운로드된 파일이나 외부 사본을 회수할 수는 없습니다.
Git에서 지운 자료가 이전 커밋에 남을 수 있으므로 실제 개인자료를 먼저 넣고 나중에 숨기는 방식을 사용하지 않습니다.

## 후속 공동 아카이브의 보안 기준

서버 기능을 도입할 때 원본 프롬프트의 아래 정책을 적용합니다.

- 게시글 공개 범위는 `public`, `shared`, `private`이며 기본값은 `shared`입니다.
- `shared`는 승인된 활성 멤버, `private`는 작성자만 읽습니다.
- 관리 역할이 다른 작성자의 개인 글 열람 권한을 자동으로 얻지 않습니다.
- 첨부파일은 상위 글 권한과 파일 자체 권한을 모두 만족해야 읽을 수 있습니다.
- 목록, 검색, 상세, 파일, 썸네일과 알림에서 같은 서버 권한 정책을 사용합니다.
- OAuth Secret, GitHub 토큰, Discord Webhook은 서버 Secret으로만 관리합니다.
- GitHub Private Repo 관리자에게 원본이 보일 수 있으므로 종단 간 암호화로 소개하지 않습니다.
- Git 저장 이력과 공개 파일의 회수 한계는 삭제 안내에도 명시합니다.

## 구현 순서와 완료 기준

1. Vite·React·TypeScript 기반, npm 스크립트와 Pages 경로 설정을 만듭니다.
2. 디자인 토큰, 반응형 홈, 프로필과 공통 탐색을 구현합니다.
3. 공개 갤러리·이야기·로그, 상세 보기와 검색·태그를 연결합니다.
4. 필요한 이미지 설정과 선택적 시연 위젯을 추가하고 저장 범위를 표시합니다.
5. 모바일·키보드·모션 감소 설정, 실패·빈 상태를 확인합니다.
6. 타입 검사·린트·핵심 테스트·빌드를 통과시키고 Pages 배포 구성을 완성합니다.

초기 완료 기준은 `npm run dev`로 사이트를 열 수 있고,
GitHub Pages의 저장소 하위 경로에서도 공개 자료 탐색과 새로고침이 정상 작동하는 것입니다.
현재 문서 작성 완료와 실제 앱 구현 완료는 구분하여 기록합니다.
